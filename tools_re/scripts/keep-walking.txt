# Walk and attack at the same time — the `--keep-walking` hook.
#
# `HERO::KeyRelease` (0x9BDCC) asks `StaticUtil::NumKeyToNaviKey` which
# navigation key was released and then overwrites the answer one instruction
# later (`mov r1,#0` at 0x9BDDC). It goes on to clear all four movement flags
# with `SetMoveKeyChk(0..3, 0)` and, if the hero was walking, to plant the
# standing animation. So releasing OK — or a skill, or the combo key — ends the
# walk even though the direction is still held down. ANALYSIS.md 37.7.
#
# This script holds a direction and attacks four times underneath it. Run it
# both ways against the same binary:
#
#   cargo run -q -p hl5_probe -- --boot --storage out/kw-off-storage \
#       --script tools_re/scripts/keep-walking.txt \
#       --count _ZN4HERO13SetMoveKeyChkEah --count 0x9be74
#   cargo run -q -p hl5_probe -- --boot --storage out/kw-on-storage --keep-walking \
#       --script tools_re/scripts/keep-walking.txt \
#       --count _ZN4HERO13SetMoveKeyChkEah --count 0x9be74
#
# Two counters, because the function does two separable things and **they do not
# affect the same classes**:
#
#   `_ZN4HERO13SetMoveKeyChkEah`  the four flag writes. The hook suppresses
#       exactly four per non-direction release, so the difference must be
#       4 x (the number of OK releases that reached `HERO::KeyRelease`).
#       Measured: 28 with the hook off, 4 with it on — and the 4 that remain
#       are the one `keyup left`, which the hook declines. That is also the
#       reason the 1,241-frame A/B stays byte-identical.
#
#   `0x9be74`  the `bl HERO::SetStandMotion` inside `HERO::KeyRelease`, reached
#       only when `CHAR::GetMainState()` says the hero was **walking**. A tap
#       attack never hits this (state is 2 at release); the stand the player
#       sees is `HERO::SetStandMotion` itself, from the attack-end path, and
#       that is the second hook (ANALYSIS.md §38.8). This counter is still
#       the KeyRelease-while-walking half.
#
# The flags matter to fewer classes than ANALYSIS.md 37.7 implies, which is
# worth knowing before reading these numbers. `HERO::IsMoveKeyChk` (0x88970)
# has exactly two callers — `GUNNER::Proc+0x228` and `KNIGHT::Proc+0x210` — and
# `HERO::IsMoveKeyNone` (0x88980) has none at all; a census of every access at
# displacement 0x1d05..0x1d08 across 100% of `.text` finds no inlined reader
# either. So for a WARRIOR or a ROGUE, clearing the flags is dead code and
# `SetStandMotion` is the whole bug. This script plays a warrior, which is why
# the second counter is the one to read.
#
# That is also why the attack is `keydown` / `frames` / `keyup` rather than
# `key`: `key` lifts OK one frame after pressing it, while the hero is still in
# the attack motion, so `GetMainState()` is not 1 and the walking branch is
# never taken. Waiting for the attack to finish first is what a player's thumb
# does anyway.
#
# The prologue is `ingame.txt`'s, up to the point where the quest popup is
# dismissed and the touch UI is on screen.
