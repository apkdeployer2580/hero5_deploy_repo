# Gamepad: the badges, and the stick that actually moves the hero.
#
#   cargo run -q -p hl5_probe -- --boot --pad --script tools_re/scripts/gamepad.txt
#
# The opening is `ingame.txt`'s, verbatim minus its screenshots — SKIP ends one
# scripted event and not the whole prologue, which is why there are a dozen of
# them. Coordinates are 400x240, so do NOT add `--screen`: the guest lays its
# menus out from `Graphic::GetWidth()` and every tap here would miss.
#
# What this replay is evidence FOR, and how to read the run:
#
#   1. The badges. `pad-connect` reports a pad, and from then on every field
#      control the map binds carries the position badge of its pad button. The
#      `pad badges N painted` line and the PNG pair are the proof; the shot
#      taken before the connect is the control, and `pad-hud off` puts it back.
#
#   2. The stick. `pad-stick 1 0` is a synthetic finger on the guest's own
#      joystick (`hl5_core::gamepad` says why a direction KEY cannot move the
#      hero in this build), so the hero must actually walk. The sharp evidence
#      is `--count _ZN4CHAR9SetMoveXYEii`: `HERO::WorkMoveHero` ends in that
#      call and only reaches it with an angle that is not −1. Run the replay
#      with and without the `pad-stick` lines and compare.
#
#   3. The queue. Two face buttons pressed inside one tick both arrive —
#      `N event(s) delivered` counts them — where the guest's own one-slot
#      mailbox would have dropped the second in silence.
#
# Do NOT put this in `ab_905.sh`'s scene list: it deliberately changes what is
# drawn, which is the whole point of the badges.
