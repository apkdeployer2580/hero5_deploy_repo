# The engineer/blacksmith screens — 제련 / 오브결합 / 조합 / 도감 / 판매.
#
#   cargo run -q -p hl5_probe -- --boot --storage out/npc-storage \
#       --script tools_re/scripts/npcmenu.txt --film out/npc-film
#
# **This scene exists because the other four do not cover it.** Across all 905
# frames of newgame + ingame + shop + online, `Battle::CallNpcMenu` is called
# exactly zero times, which leaves `DrawRefine` (4,820 B), `DrawOrbCombine`
# (4,664 B), `DrawNormalMix` (2,996 B) and `DrawCollection` (6,592 B) — 19 KB
# of drawing code — outside the byte-identity acceptance test. Those screens
# hit blitter variants `patch.rs` currently declines about 315 times every 30
# frames, so the next port to lift a decline is exactly the change that could
# corrupt them with nobody watching (ANALYSIS.md §31.6).
#
# It is the ingame.txt prefix as far as the gameplay HUD — there is no shorter
# way in, the menus need `gv+0x27C` to hold a `StateGame` — and then the eight
# jump-table entries in turn. Offline: no --server, so the boot popup gets
# dismissed the way newgame.txt does it.
#
# State numbering is `StateInNpcMenu::KeyPressed`'s 8-entry jump table. Mind
# the `addls pc, pc, rX, lsl #2` idiom when re-deriving it: **case 0 is pc+8**,
# the slot *after* the fall-through, so a naive read shifts every case by one.
#   2 판매   3 일반제련(LowRefine)   4 고급제련(HighRefine)
#   5 오브결합   6 조합   7 도감
# 0 and 1 are visited too: an entry that draws nothing is still an entry, and
# an A/B that skips it proves nothing about it.
