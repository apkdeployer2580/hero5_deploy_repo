# 장비 도감 사이트의 드랍표 생성기

배포처: <https://hero5-item-codex.vercel.app/> (Vercel 프로젝트 `hero5-item-codex`).

2026-10-11: 원본 드랍표에 있으나 원래 등급의 몬스터 드랍 경로가 없던
33종을 추가했다. 24종은 기존 몬스터 배정을 복원하고, 9종은 미사용 그룹에서
배정했다. `lostdrops::LOST_ROUTES`의 원본 그룹/밴드 → 대상 그룹은
34/4 → 35(헬 데몬), 39/4 → 38(헬 흑의병 정예),
58/4·5 → 59(헬 붉은눈·강화 시작형·루레인)이다.
원본 슬롯의 옵션은 보존한다. 일반 복원과 재배정 영웅은 대상의 밴드 3,
재배정 전설은 대상의 밴드 5 폭을 사용한다. 두 갈래 공통이다.
기존 드랍처별 확률은 유지되며 도감의 드랍처 있는 장비는 235 → 266종,
드랍 항목은 2,059개다. 추가 33종 중 에픽 장신구 2종은 도감 대상 밖이다.
원본 유효 장비 246종 모두 드랍 경로가 있으며, 실제 기기 처치 검증은 별도다.

사이트는 **자기 완결형 HTML 한 장**이고 소스가 따로 없다 — 그래서 이 파이프라인은
**배포된 페이지 자체를 템플릿으로** 쓴다. 이미지·레이아웃·세트 정보는 그대로 두고
드랍 데이터와 관련 설명문만 다시 쓴다.

```bash
cd tools_re/codex
curl -s -o codex_live.html https://hero5-item-codex.vercel.app/
PYTHONIOENCODING=utf-8 python patch_site.py      # -> codex_new.html
cp codex_new.html ../../out/hero5-item-codex/index.html
cd ../../out/hero5-item-codex && vercel deploy --prod --yes
curl -s https://hero5-item-codex.vercel.app/ | cmp - ../../tools_re/codex/codex_new.html
```

⛔ **배포는 반드시 `out/hero5-item-codex/` 에서 한다.** 그 폴더의 `.vercel/`
(프로젝트 `<vercel-project-id>`)가 **어느 프로젝트에 올릴지를 아는
유일한 것**이다. 링크가 없는 새 디렉터리에서 `vercel deploy` 를 하면 오류가 아니라
**새 프로젝트가 새 URL 로** 생기고, 사람들이 보고 있는 주소는 옛 페이지 그대로
남는다 — 로그만 보면 "배포 성공"이라 알아채기 어렵다. `out/` 은 `.gitignore` 아래라
저장소 밖이므로, 클론만 한 기계에는 그 링크가 **없다**(그때는 `vercel link` 로
`hero5-item-codex` 에 붙이고 시작한다).

마지막 `cmp` 가 인수 기준이다. `--prod` 를 줘도 CLI 는 끝에
`Promote to production` 을 안내하므로 **로그로는 프로덕션에 붙었는지 알 수 없다** —
주소에서 받아 와서 바이트로 대조한다.

> **2026-09-07 실측:** 9/4 에 만든 페이지가 배포되지 않은 채 사흘을 있었다.
> 라이브가 `codex_live.html` 로 다시 들어오는 파이프라인이라 **만들기만 하고 안
> 올려도 다음 실행이 조용히 성공한다.** 위 `cmp` 는 그것을 잡으려고 있다.

`patch_site.py` 는 **멱등**이다. 방금 배포한 페이지를 다시 템플릿으로 넣어도
바이트 동일한 결과가 나온다(설명문·CSS·칩 편집은 이미 들어 있으면 건너뛴다).

## 왜 다시 만들었나 — 옛 표는 레코드의 1/4만 읽었다

`droptable.dat` 레코드는 13바이트 `[u16 reclen=11][11바이트]` 이고, 그 안에
**(kind,index) 쌍이 셋** 있다. `Monster::SetDropItem`(0xBC910)이 `Rand(0,65535)`
하나를 몬스터의 7단 사다리에 걸어 어느 쌍을 쓸지 정한다:

| 구간 | 쓰는 바이트 | 등급 | 실측 검증 |
|---|---|---|---|
| `[0,T0)` | — | kind 13 재료, index = `enemy+0x271` | |
| `[T0,T1)` `[T1,T2)` `[T2,T3)` | — | kind = `Rand(0,9)`, index = `enemy+0x272`, **등급 0/1/2 강제** | 겨누는 324행이 전부 노멀 |
| `[T3,T4)` | `body[5],body[6]` | 표의 등급 | 240슬롯 중 **영웅 235** |
| `[T4,T5)` | `body[7],body[8]` | 표의 등급 | 144슬롯 중 **전설 112** |
| `[T5,T6)` | `body[9],body[10]` | 표의 등급 | 148슬롯 **전부 세트** |
| 그 위 | — | 아무것도 안 나옴 | |

`kind == 4`(스태프)와 `0xFF` 는 게스트가 버린다(0xBCCD8). `body[0]` 은 그룹
번호인데 게스트는 읽지 않고, `body[1..4]` 는 옵션 오버라이드 두 쌍이다
(둘째 값에 `enemy+0x274` 퍼센트가 곱해진다 — **index 에 곱해지는 것이 아니다**).

옛 표는 `body[7],body[8]` 만 읽어서 만들어졌다. 그래서 드랍처가 있는 장비가
114종밖에 없었고, 노말 대형 경비로봇·루퍼스가 실제로 떨구는 다크서클릿·빙해의투구가
`드랍 없음` 으로 보였다. 지금은 **217종 / 1,754항목**이다.

## 확률

`%` 는 **마리당**이다 — 굴림 수(`enemy+0x275`, 1~4)와 한 구간의 네 칸까지 반영한
`1-(1-w/65536 * n/4)^rolls`. **출하 확률 그대로**이고 `main`·`vanilla` 가 같은 값을
쓴다(`BRANCHES.md`). **확률 레버는 없다** — 옛 전설 밴드 상향(5%)은 2026-09-07 에
철회됐고 `rates::restore_shipped_drop_bands` 가 부팅마다 그림자를 지운다. 그래서
`drops.py` 에도 그것을 다시 켜는 인자가 없다.

**되살린 스무 행 (2026-09-08).** 출하 표가 어떤 몬스터에게 배정해 놓고 그 몬스터의
밴드 폭이 0 이라 영영 안 나오던 장비가 스물이었다. `lostdrops.rs` 가 게스트 사다리는
그대로 두고 `SetDropItem` 뒤에 한 번 더 굴린다 — 폭은 **그 몬스터 자신의 밴드 3**
(`T3 - T2`, 노말 655 / 하드 754 / 헬 852), 칸은 게스트와 같은 `Rand(0,3)`, 그리고
그 칸이 스물 중 하나일 때만 떨어진다. 그래서 **이미 나오던 것의 확률은 하나도 안
바뀐다.** 마리당 0.25~0.33%. 드랍처 있는 장비가 **217 → 235종**(스물 중 열여덟 —
쟈칼의발톱·시바스아뮬렛은 에픽이라 이 도감에 없다), 항목 1,754 → 1,895개.

호스트가 더하는 굴림의 상수(헬 보스 그룹·굴림 수·`(진)`/원본 행·세트 행 열넷·
장신구 1%·되살린 스무 행의 슬롯 표)는 **여기에 베껴 두지 않고 `hl5_core` 의 러스트에서 읽는다**
(`hl5data.rust_ints` → `legendaries.rs`·`bossdrop.rs`, 그리고 `enemy_<N>.dat` 의
레코드 오프셋은 `rates.rs`·`bossdrop.rs`). 상수 하나가 러스트에서 움직이면 이
페이지가 **아무도 안 도는 빌드의 확률을 계속 인쇄**하게 되기 때문이다. 이름이 바뀌면
파이프라인이 그 상수 이름을 대며 죽는다 — 그것이 원하는 실패다.

## 배포 전에 스스로 막는 것 셋

* **`it.d` 독자 전수 검사** — 드랍 칸의 값이 문자열에서 `[몬스터, 확률]` 쌍으로
  바뀌었다. 페이지의 소스가 어디에도 없으므로, 편집 뒤에 스크립트가 자기 출력의
  자바스크립트를 훑어 `it.d`·`it.dl` 독자가 `D_READERS` 셋뿐인지 확인하고 아니면
  **파일을 쓰기 전에** 죽는다.
* **`FOOTER_SOURCES`** — 설명문이 사실로 적은 `217종` 을 매번 다시 세어 대조한다.
  표가 움직이면 페이지가 조용히 틀린 수를 말하는 대신 여기서 멈춘다.
* **`<0.001%`** — 목록에 오른 줄은 실제로 떨어지는 줄이다. 반올림해서 `0.000%` 로
  찍으면 "안 나온다"로 읽히므로 그 아래는 부등호로 쓴다. 애초에 확률이 0 인 경로는
  목록에 오르지도 않는다(`drops.add`).
